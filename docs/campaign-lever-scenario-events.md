# Зачёт сценарных событий SmartAI для цепочки245102

Добавлено новое действие250 `SMART_ACTION_SEND_EVENT_SCENARIO`.
Параметр1 — asset события, параметры2–6 должны быть нулевыми.
Игрок выбирается стандартным GetTargets; только игрок с активным Scenario
получает UpdateCriteria(SEND_EVENT_SCENARIO, event,0,0,player).
Переход в следующий шаг остаётся под контролем native Scenario/CriteriaHandler.
Существующие действия205/206/207 и их параметры не менялись.

250 выбран вне диапазона закреплённого LegionCore(END225), в пределах
SQL tinyint. У чистого релиза нет строк action_type250. Изменение не
переписывает SQL и не начинает выполнять исходные action205 как зачёты.
Неизвестные действия между прежним END и250 по-прежнему отвергаются
веткой default загрузчика; новые числовые значения требуют явной проверки.

## Продолжение: условие, маршруты и кнопка управления

Добавлено новое native условие54 `CONDITION_SCENARIO_STEP`:
Value1 = ScenarioID, Value2 = OrderIndex текущего основного шага,
Value3 =0. Сценарий берётся у проверяемого игрока. Отсутствующий/завершённый
сценарий, другой ID/порядок или bonus-шаг не подходят. Загрузчик проверяет
существование сценария и основного шага в DB2. Поиск ограничен игроками.
Номер44 по-прежнему означает CHARMED. В чистом релизе нет записей типа54.
SQL-условия не меняются автоматически.

В закреплённом исходном ConditionMgr44 называется SCENARION_STEP и
сравнивает ScenarioID с текущим числовым шагом. Для98771 исходная проверка
задаёт сценарий962 и шаг0. В доступных DB2 у сценария962 шесть основных
шагов с OrderIndex0–5. Их entry IDs:1944/1945/1949/1953/1950/1952.
Нельзя подменять OrderIndex на entry ID962: это ID самого сценария.
Исходники:
[ConditionMgr.cpp](https://github.com/The-Legion-Preservation-Project/LegionCore-7.3.5/blob/22bfd97d0e0e30d215e408eb4da2b0419d8f00e7/src/server/game/Conditions/ConditionMgr.cpp#L412),
[Scenario.cpp](https://github.com/The-Legion-Preservation-Project/LegionCore-7.3.5/blob/22bfd97d0e0e30d215e408eb4da2b0419d8f00e7/src/server/game/Scenarios/Scenario.cpp).
Хеши файлов закреплены в `campaign-lever-dependencies-2026-10-09.json`.

Проверены оба одноточечных маршрута98836/9883600, исходная группа текста0
для98771,16 заклинаний (включая SpellHit199336), два условия, шесть шагов
и OverrideSpellData643. Аура199338 даёт кнопку199336; её DUMMY-эффект
нацелен на ближайший подходящий entry, ограниченный исходным условием13
до98836. Копирование без этого условия нарушит выбор получателя кнопки.
Native OverrideSpells уже добавляет/удаляет временное заклинание; новый
spell-handler для самой выдачи кнопки не нужен.

Десять заклинаний запускают беседы586/587/591/592/593/595/597/598/599/652.
В чистом релизе их шаблонов нет. Это **дополнительные зависимости**, не
входящие в исходный список98 бесед, из которого осталось40. Для завершения
рычага нужны их строки, актёры и длительности; наличие SpellEffect219 не
заменяет серверную conversation_template. Текущий счётчик40 не включает

прохождение целевой версии26972 ещё не подтверждено.

Native action9 и UseDoorOrButton проверены: последний не ограничивает тип
только дверью и кнопкой, поэтому сам GOOBER не является причиной отказа.
Однако полный сценарий активации и cooldown ещё требуется проверить совместно
с NPC и новой SQL-конфигурацией. Общий механизм активации не изменялся.

Новые регрессии исполняют реальные ветки evaluator, loader и search-mask54,
проверяют начальный шаг0, переход, отсутствующие/чужие данные, bonus, лишний

всех обнаруженных зависимостей в реестре. Модель/AI рычага и обеих NPC пока
не включены. Следующий крупный пакет — десять бесед и guarded SQL цепочки.
