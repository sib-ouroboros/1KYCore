# Дверь Хранителя свитков и свиток Мейтра

Восстанавливаются два отсутствующих шаблона:251591 (дверь, модель11896)
и254253 (свиток, модель36780). Добавляются только их два ранее отложенных
спавна из закреплённых кампаний:210313682 (map1625,phase6905) и210306799
(map1583,phase6068). Координаты, размеры, типы, свойства, замки2570/43 и
исходный SpellVisual58002 двери сохранены. Существующие спавны не обновляются.

## Почему требуется обработчик

В исходном LegionCore22bfd97d SmartScript action205 — UPDATE_ACHIEVEMENT_CRITERIA;
в нашем ядре205 — SET_OVERRIDE_ZONE_LIGHT. Перенос номера оставлял бы объекты
без нужной реакции. Для этих двух отсутствующих шаблонов Source
SmartGameObjectAI заменяется зарегистрированным go_campaign_scenario_interaction.
Другие номера/обработчики SmartAI и NPC AI не меняются.

Дверь при GossipHello отправляет исходному игроку criteria type92/event52452.
Сохранён source NOT_REPEATABLE на время жизни AI и Reset. Свиток отправляет
92/event54147 через native SetLootState→OnStateChanged, только при
GO_ACTIVATED=2 с инициатором-игроком. У свитка реакция повторяемая, как в источнике.
Возвращаемый false позволяет обычному движку открывать дверь/использовать
GOOBER, применять его cooldown и обновлять визуальное состояние.

Дополнительно ограничены карта и экземпляр карты инициатора, требуется
активный Scenario игрока. Игрок вне сценария не расходует one-shot двери.
Вызов Player::UpdateCriteria сохраняет misc2/misc3=0 и unit=инициатор, как
в исходном action205, и использует текущий native маршрут критериев.
Фильтр текущего шага Scenario не обходится; шаги принудительно не завершаются.
Criteria30706/34399 с Type92 и Asset52452/54147 подтверждены полным layout
Criteria.db2, включая copy-table. Источник DB2 —26654, ядро ожидает26972.

## SQL и проверки

Обновление2026_10_08_04 требует пересобранных World scripts и предыдущих
addon-schema обновлений2026_10_05_03/2026_10_08_00. Проверки всех содержательных
полей шаблонов/addon/спавнов и пользовательских SmartAI, questitem, loot,
conditions выполняются до постоянных записей. Неизвестные дополнительные
спавны этих Entry блокируют импорт. Совместимый VerifiedBuild сохраняется.
Addon публикуется раньше шаблона, спавны — последними. Прерванные префиксы
SQL можно повторить; уже опубликованный шаблон без addon отклоняется.
MyISAM не делает весь пакет транзакционно атомарным.

C++-тест компилирует настоящий AI, Player::UpdateCriteria,
Scenario::CanUpdateCriteriaTree, CriteriaMgr::IsGroupCriteriaType и
GameObject::SetLootState. Проверены регистрация, состояния, неверный/null
инициатор, чужая карта/экземпляр, отсутствие Scenario, one-shot/reset,
повтор свитка и сохранение native фильтров шагов/bonus.
SQL-тест проверяет каждое содержательное поле, несовместимые зависимости,
первый/повторный/прерванный импорт и сохранность защищённых таблиц.
Полный релиз проверяется CI; локальная БД — одноразовая копия релизных таблиц
с представительными защищёнными строками, не рабочий сервер.

[Исходные строки и DB2-доказательства](audit-data/campaign-scenario-object-restoration.json).
Остаток:41 беседа,11 отсутствующих шаблонов (100 отложенных спавнов),48 моделей.
SQL этого пакета не меняет задания, NPC AI, существующие спавны и рабочий сервер.
