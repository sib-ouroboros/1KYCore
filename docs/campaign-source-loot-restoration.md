# Восстановление объектов с исходной добычей

Миграция 2026_10_03_00_world_campaign_source_loot_objects.sql восстанавливает пять существующих заготовок: квестовые сундуки 245794, 249744, 249748; сундук 246518; рыболовную лунку 260004. Восстанавливаются модели, исходные данные, addon, пять строк добычи и три записи gameobject_questitem. Девять существующих размещений, координаты и фазы не изменяются.

## Обоснование совместимости

Проверен оригинальный код тега LegionCore735.24101, commit 22bfd97d0e0e30d215e408eb4da2b0419d8f00e7. Player::SendLoot выбирает lootid по go->GetEntry(); GameObject::IsPersonal возвращает true при chestPersonalLoot или типе награды испытания. Выбранные пять объектов не используют эту персональную ветку. Наше ядро выбирает lootid через GetLootId(), то есть Data1. Поэтому Data1 адаптировано к доказанному ключу исходных строк gameobject_loot_template; остальные исходные поля сохранены. Это явная адаптация схемы, а не догадка о назначении поля.

Исходный ChanceOrQuestChance=-100 переведён в Chance=100 / QuestRequired=1. Обычная добыча с +100 сохраняет QuestRequired=0; количество предметов также сохранено: 246518 выдаёт три 7676, 260004 — от одного до трёх 134400. Все пять Item и ItemSparse существуют в предоставленных файлах клиента; проверены layout, каталог разреженного WDC1 и границы записей, включая 42 каталожных alias. Проверка идентификаторов не является декодированием всех характеристик предметов. BroadcastText19676/37379 присутствуют в исходном и чистом release hotfix; ссылки Lock, WorldEffect и моделей проверены ранее по DB2 и включены в manifest.

Исходные 267353 и 251615 оставлены незавершёнными: LootMode=0 не проходит нативную маску LootTemplate::Process. Его нельзя молча заменить стандартным режимом без отдельного решения. Ещё 11 рассмотренных сундуков используют персональные контейнеры игрока исходного ядра; общей добычей они не заменяются.

## Защита данных

Перед постоянными записями миграция проверяет все 45 полей шаблона: допустим только точный baseline релиза или точный адаптированный шаблон. Изменённые пользователем шаблоны, addon, лишняя/несовместимая добыча, квестовые предметы и условия loot отклоняются до записи. Существующие совместимые маркеры VerifiedBuild квестовых предметов сохраняются. Для native-шаблона отсутствие обязательных addon, loot или questitem считается нарушением целостности и отклоняется.

Все исходные цели заданий и quest_template40606/42128 должны присутствовать. Запись выполняется в порядке addon → questitem → loot → native template. Поэтому прерванное применение с ещё неизменённым baseline можно повторить. Таблицы этого релиза используют MyISAM: полную транзакционную атомарность не заявляем; миграция запускается до игровых подключений, неожиданный SQL/дисковый сбой требует проверки и повторного применения. Уже изменённый native-шаблон с потерянной зависимостью автоматически не чинится поверх возможных пользовательских изменений.

## Проверки и применение

Расширена настоящая MySQL-регрессия релиза: отсутствие/изменение целей, пользовательские шаблоны/loot/условия, несовместимые режимы/количество/reference, extra строки, первая/повторная запись, смешанный baseline/native и остановка после questitem. Отдельный --source-loot-only выполняет весь этот набор первым; полный прежний SQL-набор сохраняется.

Тест test_source_loot_contract.py компилирует реальные GetLootId и LootItem::AllowedForPlayer с ASan/UBSan; проверяет выбранные loot key, нужный/уже собранный/чужой квестовый предмет, условия, отсутствие предмета и ограничение фракции. Данные Player/ObjectMgr/ConditionMgr в этом тесте — fixtures. Генерацию loot, открытие замков, состояние объекта и доступность нескольким игрокам необходимо проверить на игровом сервере.

Для применения нужен source checkout с новым SQL и включённый world updater. Живая база и release assets в этой работе не менялись. После импорта проверить все пять объектов персонажами с активным заданием/без него, ограничение количества, рыболовную лунку, повторное открытие и двух независимых игроков; 11 персональных контейнеров пока не проверять как исправленные.

Остаток отдельных инвентарей: 18 отсутствующих шаблонов / 115 размещений; 61 существующий шаблон-заглушка. Выполнено восстановление 29 из 90 заготовок; эти числа не являются процентом готовности всех кампаний.

Повторная проверка выявила три addon в clean release: 246518, 249744, 249748 с нулевыми полями. Эти точные строки добавлены как допустимый baseline только при неизменённом шаблоне-заглушке; поля addon обновляются до исходных перед активацией шаблона. Пользовательские отклонения и нейтральный addon при уже активированном native-шаблоне отклоняются. Добавлены проверки изменения каждого поля baseline addon.
