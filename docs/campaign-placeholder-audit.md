# Проверка существующих заготовок кампаний

Прежний реестр 163 шаблонов учитывал только отсутствующие строки gameobject_template. Наличие строки само по себе не означает, что объект имеет модель, правильный тип или сценарий.

Расширенная статическая сверка охватила 581 уникальный entry спавнов в 37 перенесённых Sylvania SQL (a6145c22e9ad6ac69690d4a2f7794bae4e1caf95). В чистом release у 90 из этих шаблонов displayId=0, а в исходном Legion SQL у всех 90 указан ненулевой displayId. Ни для одного из них в 37 файлах нет INSERT gameobject_template, заменяющего модель. Список: [campaign-placeholder-audit.json](audit-data/campaign-placeholder-audit.json). Указаны исходные типы, модели, AI, Data и дополнительные поля. Это отдельные кандидаты на проверку; их нет в исходном списке отсутствующих шаблонов. Общую готовность кампаний нельзя выражать прежними 132/163 (~81%).

Нулевой displayId допустим для невидимых служебных объектов. Поэтому аудит сравнивает конкретные шаблоны со своим источником, а не объявляет все нулевые модели ошибками. Список относится к чистому release и закреплённым SQL, не к фактической базе пользователя: последующие локальные обновления могли уже исправить строки. Перед изменениями выполните только чтение [campaign-placeholder-status.sql](../contrib/audit/campaign-placeholder-status.sql) на текущей world-базе.

Пример с прямой зависимостью: 245233 «Block of Fel flames» в оригинале обрабатывает SmartScript event38 SetData(1,1) -> action9 ACTIVATE_GOBJECT, self. Событие отправляет 245234 «Barrier Activator»: event70 state2 -> action45 SetData(1,1), ближайший GO245233 в радиусе30. Обе строки SmartScript отсутствуют в чистом release. Существующий шаблон 245234 там имеет type=0, displayId=0 и пустые Data/AI, тогда как оригинал — GOOBER type10, display28635, SmartGameObjectAI, Lock1691, BroadcastText33516, PlayerCondition19467, autoClose300000. Полные исходные и release-строки: [campaign-door-control-chain.json](audit-data/campaign-door-control-chain.json).

Отдельное восстановление 245233 не восстановит открытие прохода. Следует проверить Lock/BroadcastText/PlayerCondition, затем совместимость обоих шаблонов, наличие и конфликты SmartScript, дистанцию до конкретной преграды, её фазу и состояние. Объект управления имеет два перенесённых спавна. Нельзя расширять поиск до любого объекта карты или снимать замок глобально. У существующих шаблонов нужны отдельные строгие проверки соответствия заготовке; обычные пользовательские настройки должны сохраняться или прерывать импорт для ручного разбора.

Приоритет дальнейшей работы: подтверждённые цепочки открытия/квестовых предметов, затем порталы и их цели; отдельной группой — простые модели декора, если у них нет AI, заклинаний, квестовых предметов или неподдерживаемых полей. Пока аудит ничего не меняет в игровых таблицах. Классические NPC AI, питомцы и удалённые боты/наёмники этим не затрагиваются.

Группа250220–250234 (15 шаблонов простого декора) исправляется отдельной защищённой миграцией: [описание восстановления моделей](campaign-placeholder-model-restoration.md). В статическом списке90 кандидатов после неё остаётся75; реальное состояние своей базы проверяйте диагностическим запросом.
