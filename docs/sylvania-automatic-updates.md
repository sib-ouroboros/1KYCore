# Автоматическое применение исправлений Sylvania

Миграция `2026_09_30_00_world_sylvania_content.sql` переносит 37 файлов из отчёта
`upstream-sync-2026-09-30.md` в штатный каталог `sql/updates/world`. Источник —
снимок upstream `a6145c22e9ad6ac69690d4a2f7794bae4e1caf95`; SHA256 каждого
исходного файла указан перед соответствующим разделом миграции. Исходные ручные
SQL сохранены для сравнения, отдельно запускать их поверх миграции не требуется.

## Запуск

1. Сделайте резервную копию БД и обновите сервер целиком вместе с SQL из той же версии.
2. В `worldserver.conf` параметр `Updates.EnableDatabases` должен включать бит world
   (`4`). Штатное значение `31` уже включает его. Остальные биты без необходимости не меняйте.
3. `SourceDirectory` должен указывать на каталог исходников, содержащий папку `sql`.
   Например, `SourceDirectory = "/opt/1kycore/source"`; для Windows используйте свой путь.
4. В world-таблице `updates_include` должен присутствовать штатный путь
   `$/sql/updates/world`. Не добавляйте весь каталог `sql/sylvania`.
5. Запустите `worldserver`. Проверить обновление без запуска игрового мира можно
   штатным ключом `--update-databases-only`. Убедитесь в успешном завершении и записи
   имени новой миграции в world-таблице `updates`.

Updater запоминает файл и его хеш. При последующих стартах неизменённый файл
пропускается. Уже выпущенную миграцию не следует редактировать: следующие исправления
оформляются новым файлом. Бинарник без доступного SQL-каталога не доставляет миграцию.
Опубликованный дамп релиза и рабочая БД автоматически этой правкой не заменяются.

## Адаптация и границы

- Обычные INSERT преобразованы в upsert по реальным первичным ключам релизной БД.
  Обновляются только явно указанные исходником столбцы, остальные сохраняются.
- Перед изменением контента проверяется принадлежность затрагиваемых GUID существ
  и объектов ожидаемым entry. Конфликт с другим entry останавливает импорт с ошибкой
  дубликата в `_1kycore_spawn_guard`, не перезаписывая чужого NPC/объект.
- Удаление диапазонов GUID заменено адресными обновлениями. Устаревший мост удаляется
  только при совпадении диапазона GUID и старого entry. Очистка отсутствующих моделей
  ограничена импортированными парами GUID/entry и выполняется после всех кампаний.
- Остальные UPDATE/DELETE сохраняют область исправления upstream: конкретные NPC,
  задания, меню, фазы и сценарий. Собственные изменения **в этих же записях** могут
  быть заменены; это не универсальное слияние произвольных кастомных кампаний.
- У upstream отсутствует часть gameobject_template из LegionCore. Миграция не
  придумывает модели: соответствующие невалидные импортированные спавны удаляются.
  Успешный импорт не доказывает полную игровую проходимость всех кампаний.

## Проверка

Workflow `Sylvania release migration` импортирует в одноразовый MySQL 8 фактический
дамп `db-sylvania-20260926-no-mercenaries-r1` с проверкой SHA256, применяет предыдущую
сценарную миграцию и очистку ботов, затем проверяет новую миграцию:
первый запуск, повтор, восстановление после частичного выполнения, сохранность
посторонних таблиц/кастомных объектов и отказ при конфликте GUID до изменения контента.
Тест не подключается к рабочему серверу. Его результат следует смотреть в Actions;
проверка клиента, NPC и проходимости заданий остаётся отдельной игровой приёмкой.
