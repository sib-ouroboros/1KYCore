# Заказы оплота: исправления перед восстановлением объектов

Разобрана общая зависимость четырёх объектов type45: отсутствующих шаблонов
250899/250908 и моделей 252796/252800. Их контейнеры154/148/186/190 есть
в предоставленных DB2. Это обычные войска оплота; они не относятся к
удалённым ботам. Полный обработчик использования пока отсутствует, поэтому
шаблоны, модели и спавны этой группы не публикуются как восстановленные.

## Исправленный код

`StartWorkOrder` теперь обходит существующие заказы по ID. Прежний цикл
с operator[] добавлял отсутствующие ключи0,1,... и одновременно увеличивал
свой предел, вызывая рост памяти и длительный обход. Время следующего заказа
вычисляется только по его участку; переполнение срока отклоняется до создания
записи. DatabaseID сохраняется как uint64, как уже требовали загрузчик,
генератор, SQL-параметры и пакеты клиента. Поиск/удаление больше не путают
два ID с одинаковыми младшими32битами; сохранение не пропускает ID2^32.

`RewardWorkOrder` собирает ID готовых заказов перед удалением, поэтому не
использует инвалидированный итератор. Обрабатываются все подходящие рецепты
контейнера, а не только первый рецепт DB2. Будущие заказы, чужой контейнер и
отсутствующие зависимости сохраняются; повторный вызов не выдаёт уже удалённый
заказ. Существующие способы выдачи spell/item/follower не заменены.

`UpdateWorkOrders` проверяет отсутствующие данные участка и неудачный summon.
Каждый участок получает один результат: наличие хотя бы одного готового
заказа сохраняет готовый вид независимо от порядка unordered_map.

Это исправление ошибок общих методов, не завершённая система получения
наград. Перед включением объектов необходимы проверка владельца/оплота,
полного инвентаря и лимита войск, защита от повторной выдачи при сбое БД,
персональная принадлежность объектов и проверка пакетов в клиенте26972.
Текущая выдача item/follower ещё не гарантирует восстановление при отказе;
обработчик взаимодействия с этими объектами не добавляется.

## Проверки и реестры

Тест компилирует настоящие пять методов и структуру WorkOrder, включает
проверку итераторов libstdc++ и в CI ASan/UBSan. Проверяются разреженные и
большие ID, несколько рецептов, готовность на границе времени, повтор,
переполнение, отсутствующие зависимости, ошибки создания и смешанный участок.
Локально тест прошёл с GCC и Wall/Wextra/Werror, без sanitizers.
SQL не требуется: структура БД уже использует64битный ID; данные не меняются.
