Объекты268377–268379 пока **не восстановлены**. Проверены три связанных
спутника119619–119621, шесть точек маршрутов, девять заклинаний и три

Две исходные строки снимают ауру другого спутника. Это подтверждено цепочкой
APPLY_AURA428 → TriggerSpell → SUMMON, а не совпадением названий.
До сверки hotfix нельзя объявлять исходный сервер ошибочным: там могла быть
иная таблица эффектов. Копировать строки без проверки в наше ядро нельзя.

Все три SummonProperties имеют Control1, Title0 и Personal Spawn0x10.
4032/4033 являются копиями4031 в WDC1; отсутствие отдельной физической строки
не означает отсутствие записи. Native EffectSummonType передаёт признак
персональности в SummonCreature. Это обычные союзные TempSummon, а не PetAI.
Дополнительный перенос исходного действия207 не нужен для этой видимости:
в нашем enum207 означает изменение угрозы и приведёт к иной логике.

Есть отдельная проблема жизненного цикла: HandleLinkedSummon при удалении
ауры немедленно вызывает DespawnOrUnsummon для принадлежащего игроку NPC.
Последовательность SetData → маршрут → RemoveAura оборвёт уход спутника.
Нужна ограниченная тремя квестовыми аурами обработка возвращающихся NPC,
проверка владельца при выборе получателя и завершение по двум исходным точкам.
Общий обработчик linked summon нельзя менять ради этих трёх объектов.

Перед публикацией моделей нужны тесты двух игроков, повторной доставки,
нового спутника при ещё уходящем старом, снятия ауры вне доставки, выхода
игрока и недоступного маршрута. Требуются также защищённые SQL-привязки
скриптов, проверка требований квеста45440 и прохождение в клиенте.
Маршруты и зачёты сохранены в отчёте; квесты, AI и спавны не изменялись.

Воспроизводимая проверка сохранённого свидетельства:

```powershell
python contrib/tools/campaign_brew_chain_audit.py --output brew-review.json
python contrib/tests/test_campaign_brew_chain.py
```

Инструмент работает с закреплёнными свидетельствами и не извлекает DB2 заново.
Он отклоняет неполные маршруты, потерю персональности, pet-category,
не-linked ауру и неоднозначную цепочку призыва. JSON свидетельства содержит
хеши DB2 и декодированные поля; это не подтверждение клиентского прохождения.

Остаток сохраняется:40 бесед,11 шаблонов,46 моделей. Этот пакет закрывает
аудит зависимостей трёх моделей, но не включает их в восстановленные.

## Реализация жизненного цикла

Добавлены обработчики в `campaign_brew_scripts.cpp`: сопровождение и
двухточечный уход NPC, доставка у бочки, сохранение уходящего спутника при
снятии linked-ауры. Loader регистрирует обработчики. **SQL-привязки ещё не
добавлены, модели пока не включены.** Остаток40/11/46 сохраняется.

Соответствие аура/призыв/NPC определяется из загруженного SpellMgr.
Перестановка двух корректных связей в hotfix поддерживается; отсутствие или
две ауры одного спутника запрещают доставку. Игрок должен иметь незавершённый
45440 и нужную ауру. Выбирается только живой TempSummon того же игрока в
той же фазе, в радиусе100, с новым AI. Соседний игрок не получит зачёт
и не потеряет NPC. Повторное использование не перезапускает маршрут.

Снятие ауры без уходящего NPC продолжает использовать native обработчик.
Если старый спутник уже уходит и рядом появился новый, сохраняется только
старый, новый удаляется при отмене ауры. Общий HandleLinkedSummon не менялся.
Восстановлены шесть исходных точек; уход заканчивается удалением NPC.
Через30 секунд предусмотрена очистка застрявшего уходящего спутника. Этот
таймаут — новая защитная мера, а не подтверждённая оригинальная длительность.

Регрессия компилирует реальный файл обработчиков с контролируемыми границами
движка и выполняет доставку для всех трёх объектов, два владельца, отмену,
повторную доставку, неверную фазу/карту, радиус, отсутствие квеста/ауры,
совместное существование старого/нового NPC, обе точки и таймаут. Заголовки
движка заменены тестовыми интерфейсами: полная сборка обязательна отдельно.

```powershell
python contrib/tests/test_campaign_brew_scripts.py --compiler c++
```

Следующая часть — guarded SQL для трёх GO и трёх NPC, spell_script_names,
MySQL-тесты конфликтов и повторного импорта. Только после неё можно
пересчитывать восстановленные модели. Клиентское прохождение также остаётся.
