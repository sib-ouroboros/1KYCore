# Общие зависимости оставшихся объектов кампаний

Пакет проверяет все текущие 59 объектов: 11 отсутствующих шаблонов и 48
моделей-заготовок. Использованы закреплённые исходные SmartScripts из
LegionCore commit 22bfd97d0e0e30d215e408eb4da2b0419d8f00e7 и БД
LegionCore_world_735.26972_2024_10_23.sql. SHA256 входных файлов включены
в JSON; генератор отклоняет другие файлы. Это аудит зависимостей, а не
восстановление поведения объектов.

## Обнаруженные различия

Для каждого кандидата собраны собственные GO-entry строки, входящие ссылки
по entry, получатели SetData и фиксированные timed lists. В исходной таблице
71889 строк SmartScript. Получатели SetData проверены по event38 и паре
параметров; цепочки включают строки обычных NPC, но не изменяют их.

* Объекты 251262 и 252981 используют source204 SET_SCENATIO_ID, тогда как
  native204 означает CIRCLE_PATH. Нужен проверенный переход сценария.
* Для 246148 и связанных цепочек 245102/245924 source205 означает обновление
  критериев, native205 — освещение. Перенос требует обработки native criteria,
  текущего шага и остальных зависимостей; копирование числовых действий неверно.
* Объекты 251697, 266166, 266594, 267041 запускают беседы
  2851, 4678, 4576, 4269. Их зависимости рассматриваются отдельно от текущих
  41 беседы из импортированного пакета: отчёт не считает их восстановленными.
  Разные имена source206/native206 сами по себе не доказывают несовместимость.
* Для бочек 268377/268378/268379 получатели 119620/119621/119622 имеют source207
  SUMMON_ADD_PLR_PERSONNAL_VISIBILE; native207 означает MODIFY_THREAT.
  Получатель также следует игроку, запускает waypoint и исчезает. Одних GO
  SetData/credit/remove-aura недостаточно: нужна персональная видимость,
  правильный владелец и путь движения. Нельзя просто импортировать эти NPC AI.

Ограничения: не охвачены ссылки по GUID, случайные timed lists, полный граф
spell/event/waypoint, runtime-условия и совпадение обработчиков release/native.
Совпадение названий enum не подтверждает совместимость параметров. Отчёт
сохраняет точные source-строки для последующего ручного анализа.

## Исправления общей системы оплотов

GetFollower и GetMission теперь ищут полный 64-битный ключ. Раньше сравнение
младших 32 бит могло привязать способности/награды к другой записи при загрузке
или выбрать другого соратника при отправке на миссию. Структуры, чтение БД,
сохранение и пакеты уже используют uint64; SQL-миграция не нужна.

GetAverageFollowerILevel возвращает 0 для пустого/полностью неактивного состава.
Сумма вычисляется в uint64, округление вверх выполняется целочисленно.
Follower::GetItemLevel расширяет сумму до uint64 перед сложением.
HasAbility пропускает nullptr, сохраняя поиск остальных способностей.

Регрессия компилирует десять настоящих методов Garrison.cpp. Проверяет
совпадение младших битов ID, 2^32, UINT64_MAX, rehash, отсутствие вставок при
поиске, повторное удаление, различие DB ID/mission record ID, принадлежность
миссии, активный состав, округление, переполнение и null ability.
Локально GCC/Wall/Wextra/Werror/checked iterators проходят; CI использует
ASan/UBSan. Тест заказов и существующий тест жизненного цикла миссий проходят.

## Воспроизведение

```powershell
python contrib/tests/audit_campaign_script_chains.py --source-world <original-world.sql> --source-header <original-SmartScriptMgr.h> --output docs/audit-data/campaign-script-chain-inventory-2026-10-08.json
python contrib/tests/test_campaign_script_inventory.py
python contrib/tests/test_garrison_identity.py
```

Windows без доступного runtime sanitizer: добавить --no-sanitizers последней
команде. Для остальных тестов используется штатный CI.

Остаток: **41 беседа, 11 шаблонов / 100 отложенных спавнов, 48 моделей**.
Новые объекты не включались; SQL, NPC AI, задания и рабочий сервер не менялись.
Клиентская проверка ранее восстановленных объектов всё ещё требуется.
