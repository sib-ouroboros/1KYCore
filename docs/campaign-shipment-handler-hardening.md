# Обработчики очередей и выдача заказов оплотов

Пакет дорабатывает общую зависимость объектов 250899/250908/252796/252800.
Это обычные войска оплотов. Механика удалённых ботов и наёмников не возвращается.
Объекты type45 пока не включаются: следующие ограничения перечислены ниже.

## Исправления

Три обработчика GarrisonHandler.cpp переработаны вместе:

* Landing-page обходит реальные пары карты по ссылке. Старый обход локальной
  копии unordered_map через operator[] создавал записи 0,1,... и увеличивал
  предел цикла. Для обычных разреженных database ID это могло зациклить запрос.
* Shipment info использует список заказов выбранного участка, фильтрует
  повреждённые записи до подсчёта и выводит ровно объявленное число строк.
  Проверяются наличие контейнера, оплота, допустимый NPC, участок и присутствие
  игрока в оплоте. Пустой участок отправляет корректный пустой пакет.
* Create shipment ограничивает количество свободными местами относительно
  MaxShipments — той же ёмкости, которую существующий info-пакет сообщает
  клиенту. Это восстановление ранее закомментированного ограничения очереди,
  а не реализация лимита количества войск. Нулевая ёмкость запрещает создание.
  Count=0 сохраняет прежний смысл одного заказа; пакет клиента не изменяется.
  Spell и успешный ответ отправляются только после успешного StartWorkOrder.
  Частичный отказ прекращает цикл; уже созданные заказы остаются действительными.

Landing-page сообщает настоящий тип оплота. AssignedFollowerDBID остаётся 0:
в WorkOrder нет назначения существующего соратника; GarrFollowerID рецепта —
ID шаблона DB2, а не database ID назначенного соратника. Сериализаторы и
формат остальных полей не изменялись. Записи с нулевым ID, отсутствующим
рецептом или обратными временными границами не отправляются клиенту, но не
удаляются из БД. Вместимость считает все существующие заказы выбранного участка.

RewardWorkOrder предварительно проверяет обязательный completion spell и
шаблон соратника. При AddItem(count=1)==false заказ сохраняется, последующие
эффекты/соратник не выдаются. При успехе выдача продолжается и заказ удаляется.
AddShipmentFollower теперь сообщает отказ отсутствующего шаблона через bool.
Рецепт без реализуемого spell/item/follower сохраняется: TreasureID пока не
обрабатывается. Внутри процесса повтор не выдаёт удалённый заказ повторно.

## Проверки

Новая регрессия компилирует три настоящих обработчика, GetBuildingWorkOrders
и два настоящих packet Write. Фикстуры проверяют разреженные ID выше 32 бит,
несколько участков/рецептов, побайтовую длину/поля пакетов, пустые очереди,
повреждённые данные, отсутствие зависимостей, UINT32_MAX в Count, полную
очередь, Count=0, нулевую ёмкость и полный/частичный отказ StartWorkOrder.
Mock packet buffer выполняет little-endian запись; это проверка штатных
писателей, не клиентское воспроизведение сетевого протокола.

Существующая регрессия настоящих методов work orders расширена полным
инвентарём, повтором после освобождения места, отсутствующим spell/follower,
неподдержанным рецептом и восстановлением зависимостей. Также прошли
проверки identity/roster, mission lifecycle и счётчиков кампаний.
Локально GCC/Wall/Wextra/Werror/GLIBCXX_DEBUG без sanitizers; Linux CI
запускает ASan/UBSan. Клиентская проверка отдельно необходима.

## Что ещё требуется до включения объектов

* Native type45 Use, связь владельца с персональным объектом участка и respawn.
* Полное списание ресурсов/реагентов и ограничения найма войск. Прежний
  triggered spell остаётся; пакет не утверждает, что оплата заказов реализована.
* Атомарная/восстанавливаемая выдача и удаление заказа при перезапуске или
  отказе БД. AddShipmentFollower сохраняется отдельно, поэтому crash между
  выдачей и удалением может повторить награду; этот риск ещё не устранён.
* Награды TreasureID и достоверные modifier/capacity upgrades.
* Тест двух игроков, клиент 26972, перезаход и перезапуск.

В этом пакете SQL, NPC AI, задания, спавны и рабочий сервер не изменяются.
Остаток сохраняется: **41 беседа, 11 шаблонов / 100 отложенных спавнов,
48 моделей**. Исправление зависимости не засчитывается как восстановление GO.
