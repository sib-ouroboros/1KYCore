# Первая группа исправлений после аудита

Ветка `development/character-tools`. Основание: [аудит](campaign-and-build-audit.md).

## Очистка и загрузка наград гарнизона

`GarrssionMissionRewardMap` — vector значений, а не указателей. Убрано удаление
адреса локального итератора. Очистка выполняется штатным `clear()`.
Награды теперь создаются как локальные значения и копируются в vector, без
утечки выделенного через `new` объекта. Повторная загрузка заменяет прежние
данные, порядок и четыре поля награды сохраняются. Пустой результат очищает
ранее загруженные награды, как и прежде.

## Неактивное задание у тренера боевых питомцев

`OnGossipSelect` явно возвращает false, когда нужный объект задания не активен.
Это соответствует штатной обработке NPCHandler: ядро может обработать меню
самостоятельно. Очистка меню перенесена внутрь обработанной ветки, чтобы
не уничтожить данные меню перед этим fallback. Создание боя, подбор питомцев
и ветка активного задания не изменены.

## Шесть простых шаблонов и 35 спавнов

Новая миграция `2026_10_01_00_world_campaign_generic_objects.sql` восстанавливает:

| Entry | Название исходника |
|---:|---|
| 226941 | Blood spatter |
| 245435 | Armor Stand |
| 246161 | Round Table |
| 246419 | Boat |
| 246420 | Bonfire |
| 246429 | Compass |

Все шесть — `GAMEOBJECT_TYPE_GENERIC` (5), без AIName/ScriptName, заклинаний,
лута, DataN, questItemN, дополнительных визуальных эффектов, faction/flags
и золота. Модели, имена, размер и VerifiedBuild взяты из закреплённого архива
LegionCore, координаты/фазы — из закреплённых источников Sylvania. Полный список
GUID и источников: [реестр группы](audit-data/campaign-generic-restoration.json).

До изменений проверяются:

- GUID, занятый другим entry: миграция останавливается;
- addon/questItem для отсутствующего шаблона с ненулевыми параметрами:
  миграция останавливается, не переосмысливая осиротевшие данные;
- существующий шаблон с другим типом, скриптом или ненулевыми DataN:
  миграция останавливается, не создавая спавны с иной механикой.

Остановка происходит с Duplicate entry в `_1kycore_generic_guard` до записи
в игровые таблицы. Для совместимых существующих шаблонов сохраняются их поля,
для существующих GUID с ожидаемым entry сохраняются координаты и фазы.
Добавляются только отсутствующие записи. Старые миграции не редактируются.

Обновление применяется штатным world updater при доступном каталоге SQL,
как описано в [инструкции](sylvania-automatic-updates.md). Оно не меняет дамп
опубликованного релиза и не восстанавливает остальные 157 шаблонов реестра.
Сложные типы и дополнительные визуальные поля остаются отдельными группами.

## Проверки и ограничения

`test_garrison_reward_reload.py` компилирует реальные loader/getter с тестовой
БД и строгими ASan/UBSan: 100 повторных загрузок, сохранение полей/порядка,
замена/пустой результат и независимость возвращённой копии. Для тренера
проверяется реальный eligibility gate и пути возврата, с заменой создания боя
тестовым счётчиком. Полное создание боя эта проверка не симулирует.

`test_sylvania_migration.py` расширен проверками на одноразовом MySQL с реальным
релизным дампом: восстановление, повтор, прерывание после шаблонов, сохранность
кастомных записей/посторонних таблиц и отказ при каждом конфликте до изменения
данных. Результаты смотреть в GitHub Actions.

Полные сборки проверяют компиляцию настоящих методов. Реальные DB2 моделей,
появление объектов в нужных фазах и бой питомцев нужно проверить в клиенте;
эта небольшая группа не доказывает проходимость всех классовых кампаний.
