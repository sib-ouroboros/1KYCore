# База данных для 1KYCore

Этот пакет содержит исходную базу DestinyCore DB735.02 и SQL из указанного в
`database-source.json` коммита 1KYCore. Исполняемые файлы сервера поставляются отдельно.
Архив базы не изменён и не очищен от данных удаляемых модулей.
Импорт и совместимость с работающим сервером пока не проверены.

## Состав и проверка

- `DB735.02.rar`: дампы `world` и `hotfixes` из
  [релиза DestinyCore](https://github.com/slash-design/DestinyCore/releases/tag/DB735.02).
- `1KYCore-database-support-<commit>.zip`: схемы `auth`, `characters`, `shop`,
  каталоги `sql/updates`, `sql/custom`, эта инструкция и лицензия проекта.
- `SHA256SUMS`: контрольные суммы трёх файлов пакета.
- `database-source.json`: источник, версия базы и полный SHA коммита SQL.

На Linux: `sha256sum -c SHA256SUMS`. В PowerShell используйте
`Get-FileHash .\DB735.02.rar -Algorithm SHA256` и сравните с `SHA256SUMS`.
Скрипт упаковки сам проверяет размер и закреплённый SHA-256 исходного RAR.

## Установка с нуля

Используйте пустые базы. Повторный импорт полных дампов в рабочую базу может
заменить её данные; этот пакет не является миграцией существующего сервера.

1. Распакуйте RAR и ZIP. Сохраните структуру `sql/` из ZIP.
2. Создайте базы `auth`, `characters`, `shop`, `world`, `hotfixes` и отдельного
   пользователя MySQL с правами на эти базы. Укажите свои пароли в конфигурации сервера.
3. Импортируйте `sql/base/auth_database.sql` в `auth`,
   `sql/base/characters_database.sql` в `characters`,
   `sql/base/shop_database.sql` в `shop`.
4. Импортируйте `DB_world_735.02.sql` и `DB_hotfixes_735.02.sql` из RAR.
   Согласно инструкции исходного проекта, дампы содержат `CREATE DATABASE` и `USE`;
   проверьте эти строки, особенно если используете другие имена баз.
5. В `worldserver.conf` укажите `SourceDirectory` как абсолютный путь к папке,
   внутри которой расположен распакованный каталог `sql`. Используйте
   `Updates.EnableDatabases = 31` и `Updates.AutoSetup = 1`.
6. Запустите сервер соответствующей версии и проверьте журнал применения обновлений.
   Не импортируйте `sql/updates` вручную: ими управляет механизм обновления ядра.

Пустые схемы `sql/base/dev` и необязательные ручные исправления `sql/sylvania`
в пакет не включены. SQL из `sql/updates` соответствует указанному коммиту ядра. Старые обновления
справочников ботов выведены из эксплуатации; их имена сохранены для истории обновлений.

## Подготовка нового пакета

Требуются Git и Python 3.11 или новее. Из чистого checkout нужного коммита:

```text
python contrib/release/prepare_database_release.py --output <папка-вне-репозитория>
```

SQL берётся из Git-коммита `HEAD`, а не из незакоммиченных файлов. Проверенный
RAR повторно используется при наличии в выходной папке. Для каждого коммита
используйте отдельную выходную папку, чтобы не смешивать версии SQL.

Workflow `Database release` проверяет упаковку при изменении инструкции или
скрипта. Ручной запуск дополнительно создаёт черновик prerelease с новым тегом
`db735.02-...`. Существующие релизы не перезаписываются. Для ручного запуска
через интерфейс Actions workflow должен присутствовать в основной ветке.

## Очистка удалённых модулей

В cleanup/remove-bots обновления 2026_09_29 удаляют шесть служебных таблиц:
auth: playerbot_arena, playerbot_names; world: ai_playerbot_names, ai_playerbot_locks;
characters: capital_siege_state, capital_siege_history. Эти данные больше не используются
кодом. Аккаунты, персонажи, имущество и гильдии не удаляются.

Старые SQL больше не загружают 165923 строки справочников имён. Имена файлов оставлены:
механизм обновления повторно применяет изменённый файл при несовпадении SHA1.
Поэтому toolip создаётся только при отсутствии, а aiwaypoints заполняется только
при создании новой таблицы. Существующие координаты, IP-привязки и намеренно пустая
таблица сохраняются. Обновление world удаляет 30 точек старого маршрута осады
только при полном совпадении ID, карты, координат, link и helpText; изменённые точки остаются.

Для существующего сервера перед обновлением сохраните резервную копию баз и используйте
автоматический updater. Проверьте его журнал: при отключённых обновлениях очистка не выполнится.
Новый SQL-support ZIP не изменяет исходный DB735.02.rar или ранее выпущенные архивы;
очистка содержащихся в них данных выполняется миграциями после импорта.

Workflow Bot database cleanup проверяет SQL на отдельном MySQL 8.0: новый набор таблиц,
обновление существующих данных, пустую таблицу координат и повторное применение.
Это не тест полного импорта внешнего дампа или игрового поведения worldserver.
