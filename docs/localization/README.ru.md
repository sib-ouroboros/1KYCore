## Безопасная модель пакетов

Меняются только разрешённые ruRU-поля либо `trinity_string.content_loc8`.
Непустой перевод сохраняется; точная английская копия заменяется только после
сопоставления соответствующего английского поля и назначения. Кириллица сама по
себе не является достаточным критерием. Все принятые строки проверены на токены,
параметры форматирования, ссылки, управляющие символы, длину и кодировку.
Не совпавшие исходники/привязки и сомнительные тексты направлены в очередь.

Пакеты используют compare-and-set: перед любыми постоянными записями проверяют
схему, PK, длины, ожидаемые тексты и привязки. Поиск использует индекс ключа и
дополнительное бинарное сравнение. Коллизии case-insensitive PK, включая `ruru`,
также отклоняются. Повторное применение допустимо; частично выполненный пакет
можно повторить после устранения причины остановки.

Новые locale-строки заполняются штатными defaults, `VerifiedBuild=0`, с доказанным
ruRU-ключом; существующие VerifiedBuild и все нецелевые поля остаются прежними.
Происхождение не прячется в VerifiedBuild: источник, ключ, поле и хеши есть в манифесте.
Отсутствующие базовые игровые сущности никогда не добавляются.

Откат существующей строки восстанавливает только собственные изменённые поля.
Удаление добавленной строки разрешено только при точном совпадении **всей**
строки после импорта, включая служебные поля. Любая чужая последующая правка
вызывает отказ, а не перезапись. Временная MEMORY-таблица служит только проверке
конфликта и исчезает с соединением; постоянные служебные таблицы не создаются.

World содержит MyISAM и InnoDB. Атомарность транзакцией не заявляется:
нужны остановленный тестовый сервер, резервные копии и прекращение обработки
при первой ошибке. **Не использовать `--force`** и не продолжать следующий пакет
после ошибки. Не запускать одновременно с игровыми/административными записями.

## Просмотр, установка и откат на своей тестовой копии

В этой работе применялись только отдельные локальные scratch-базы. Ниже инструкция
для ручной проверки; действующий сервер и его конфигурация не изменены.

1. Подготовить независимые world/hotfixes: релиз из `sources.json`, затем миграции
   актуальной ветки по правилам проекта. Версия дампа, client build и VerifiedBuild
   не взаимозаменяемы. Проверить структуру, кодировку и целевые записи.
2. Остановить **тестовый** worldserver. Сделать полные бэкапы обеих баз; для смешанных
   движков использовать `mysqldump --lock-all-tables`, а не обещать защиту MyISAM
   опцией `--single-transaction`. Проверить восстановление бэкапа на ещё одной копии.
3. Просмотреть предложения и извлечь SQL вне репозитория:

```sh
python3 tools/localization/bundle.py inspect --input sql/optional/ruRU/2026-10-04/world --category quests --limit 10
python3 tools/localization/bundle.py extract --input sql/optional/ruRU/2026-10-04/world --output /tmp/1ky-ru-world
python3 tools/localization/bundle.py extract --input sql/optional/ruRU/2026-10-04/hotfix --output /tmp/1ky-ru-hotfix
```

`accepted-fields.jsonl.gz` содержит читаемые enUS/current/ruRU и классификацию;
`manifest.json.gz` — источники и точные хеши каждой принятой строки/поля.
`catalog.json` проверяет gzip и распакованный SQL. Он обеспечивает целостность,
а не заменяет доверие к источнику и ревью. Извлечение не обращается к СУБД.

4. Применить `.apply.sql` в порядке имён к соответствующей тестовой базе.
   Обработку остановить при первой ненулевой ошибке mysql. Не направлять hotfix
   SQL в world. Пустой poi-bundle содержит только отчёт и не требует применения.
   Пример POSIX для **ранее настроенного локального тестового** login-path:

```sh
set -eu
for f in /tmp/1ky-ru-world/*.apply.sql; do mysql --login-path=localization-test --default-character-set=utf8mb4 world_review < "$f"; done
for f in /tmp/1ky-ru-hotfix/*.apply.sql; do mysql --login-path=localization-test --default-character-set=utf8mb4 hotfix_review < "$f"; done
```

5. Повторить применение, проверить неизменность данных, затем запустить тестовый
   worldserver и пройти сценарии из `validation.ru.md`. После установки перезапуск
   нужен для стабильной проверки всех загрузчиков, особенно DB2/hotfixes.
6. Для отката остановить тестовый сервер и выполнить соответствующие `.rollback.sql`
   в обратном порядке. Например, `find /tmp/1ky-ru-world -name '*.rollback.sql' | sort -r`
   даёт список; применять каждую запись с остановкой при ошибке. При конфликте
   сравнить манифест, актуальный текст и backup; не заменять guard на `--force`.

## Автоматическое применение при запуске

Обычные `.apply.sql` включены в `sql/updates/world/ruRU` и
`sql/updates/hotfixes/ruRU`. Это точные распакованные копии проверенных пакетов:
525 файлов, только применение. Архивы, манифесты и откаты сохранены отдельно
в `sql/optional/ruRU/2026-10-04`. C++ updater не изменён.

При запуске worldserver штатный updater сначала выполняет остальные текущие
миграции, затем эти файлы (префикс `zz_`). После успешного выполнения каждого
пакета записывает его имя и SHA1 в `updates` соответствующей базы. Следующие
запуски пропускают уже применённые неизменные файлы. Ранее вручную применённые
пакеты допускают повторный импорт и регистрацию штатным updater.

В `worldserver.conf` необходимо включить обновления world и hotfixes:

```ini
Updates.EnableDatabases = 31
SourceDirectory = "/полный/путь/к/исходникам/1KYCore"
```

Маска 12 включает только world и hotfixes; 31 также включает остальные штатные
базы. SourceDirectory должен указывать на эту ветку с каталогом `sql`, доступным
серверу. Одних бинарников недостаточно. Клиент mysql должен быть доступен через
PATH или `MySQLExecutable`. Не включать `force` в настройках mysql: updater должен
получить ненулевой результат при первой SQL-ошибке. Конфликт проверок останавливает
запуск; не удалять guard и не продолжать обработку вручную с `--force`.

Перед первым запуском подготовить резервные копии и проверить независимую
тестовую копию. Импорт выполняется до загрузки игровых данных; во время него
другие серверы и административные процессы не должны писать в эти базы.
Смешанные движки не обеспечивают атомарность всего набора пакетов: после
исправления причины ошибки незавершённый пакет можно повторить при новом запуске.

Для загрузки русских hotfix-текстов нужны настройки локалей ниже; SQL-обновление
само по себе не меняет конфигурацию и язык клиентов.

Для отката использовать отдельные `.rollback.sql` из optional-пакетов на
остановленном сервере, как описано выше. Оставить записи `updates` с контрольными
суммами и исходные файлы неизменными: следующий запуск пропустит успешно
зарегистрированные пакеты. Не очищать их хеши, иначе updater может снова выполнить
импорт. Для пакета, не успевшего зарегистрироваться из-за ошибки, сначала отдельно
решить повторное применение либо отключить обновления на время отката.

Проверка соответствия SQL исходным архивам, порядка и списка файлов:

```sh
python3 tools/localization/export_updates.py --check
```

`automatic-updates.json` содержит пути, размеры, SHA256 и SHA1 updater.
Python нужен только для проверки/воспроизведения файлов, а не для запуска сервера.

## Клиент, локали и голоса

Текущий `auth_database.sql` допускает несколько builds 7.3.5, default realm build
**26972**; `RealmList::LoadBuildInfo` и realm Build используют реальные данные auth.
DB2 layout тоже проверяется ядром. Клиент не менялся; номер 26124 в имени донора
не является указанием переключить сервер или подделать VerifiedBuild.

`DBC.Locale=0` оставлен как был. Эта настройка выбирает основной каталог DB2,
а не язык всех пользователей. `WorldSession` хранит отдельно DB-локаль сессии
и доступную DBC-локаль. Для русского клиента нужны его штатные ресурсы и
локализованные DB2 той же совместимой версии; извлекать их инструментами проекта
из собственного клиента. SQL не создаёт русский UI, озвучку или клиентские файлы.

Для теста новых русских BroadcastText при enUS default нужны:

```ini
DBC.Locale = 0
DB2.Hotfix.LoadData = 1
DB2.Hotfix.LoadStrings = 1
DB2.Hotfix.LoadAllLocales = 1
DB2.Files.LoadAllLocales = 1
```

Это пример настройки **тестовой** среды, а не изменение поставляемого default.
`LoadAllLocales` нужен для ruRU hotfix-строк при enUS основном каталоге.
При отсутствии ruRU функция остаётся на английском; язык enUS-сессии сохраняется.
Предоставленные локальные enUS/ruRU BroadcastText.db2 имеют WDC1 layout 0x51BF0C33
и по 3 894 ID, но не содержат 27602: эта запись уже присутствует в целевых hotfixes
с обеими русскими формами и VerifiedBuild 19865. Ресурсы не копировались в Git.
Header/ID-проверка не подтверждает остальные DB2, весь build или работу клиента.

## Воспроизведение

Python 3.12, без сторонних Python-пакетов. `--help` есть у каждого CLI.
Дампы — только доверенные файлы с указанными SHA; неизвестный SQL донора не запускать.
Парсер поддерживает документированное подмножество MySQL dump: CREATE, literal
INSERT/REPLACE, quoted columns, NULL, multiline и escapes; неизвестный выбранный
синтаксис завершается ошибкой. DROP/LOCK/ALTER KEYS и DELETE пустой таблицы в
dump preamble только читаются, никогда не выполняются инструментом.


Целевой world snapshot получен mysqldump 8.0.45 после 24 миграций ветки;
нужны все существующие таблицы `rules.selected_tables()`, кроме отсутствующего
у target donor-only `creature_template_wdb`/`creature_template_wdb_locale`/`locales_gameobject`.
Экспортировать **наличные** имена из selected_tables, сортировать по имени, options:
`--skip-comments --skip-add-locks --skip-disable-keys --no-tablespaces
--set-gtid-purged=OFF --column-statistics=0 --skip-triggers --order-by-primary`, UTF8MB4.
Поле `gossip_menu_id` берётся из того же creature_template, не из внешнего guess-файла.
POI — отдельный snapshot двух таблиц, режим `--database poi`; checksum в sources.json.
Если snapshot отличается, использовать фактический SHA и получить новый отчёт;
не обходить отказ старого пакета. CSV экранирует формулы для безопасного просмотра.
